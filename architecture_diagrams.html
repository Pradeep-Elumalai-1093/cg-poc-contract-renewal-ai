2. Application flow — daily batch run

What happens end to end when the daily batch is triggered. The middle step, "agent graph," is expanded into its own detailed section below — here it's one box on purpose, to keep the top-level flow readable.

3. Agent graph — how the five agents connect

Two agents run independently ahead of time, cached by id. The other three run sequentially per milestone, with a retry loop between recommendation and evaluation.

Neither agent waits on the other. Caching means most batch runs skip both entirely after the first run for a given contract/customer.

Policy-compliance failure is a hard fail regardless of composite score. A passing recommendation always reaches the content agent before the trace is logged.

How the React frontend, FastAPI backend, and the swappable LLM provider connect. Region and channel are configuration, not forked code — one engine serves NATT, ETT, and APAC TT.
